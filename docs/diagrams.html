HTTP Request Flow

End-to-end sequence for a POST /query request — from middleware span enrichment through the four pipeline nodes, three parallel tool calls, and the final compliance log write. 

%%{init:{'theme':'dark'}}%%
sequenceDiagram
    participant C  as Client
    participant FI as FastAPI + OTel Instrumentation
    participant MW as TelemetryMiddleware
    participant EP as query() endpoint
    participant PP as run_pricing_pipeline
    participant VQ as validate_query
    participant FD as fetch_deal_data
    participant CP as compute_pricing
    participant CR as emit_compliance_record
    participant CE as emit_compliance_event
    participant FS as compliance_events.jsonl

    C->>FI: POST /query  {deal_id, query_category}
    FI->>FI: Create root SERVER span (W3C traceparent header)
    FI->>MW: dispatch(request)
    MW->>MW: extract / generate run_id (UUID)
    MW->>MW: enrich active span: service.run_id, http.route, service.name, pod
    MW->>EP: call_next(request)
    EP->>EP: set_baggage_on_current_context(query.category, business_unit, ...)
    EP->>PP: run_pricing_pipeline(deal_id, query_category, config)
    PP->>PP: init_agent(config)  —  set module-level _config
    PP->>PP: get_current_trace_id()  →  state["run_id"]
    PP->>VQ: validate_query(state)
    note over VQ: INTERNAL span — checks required keys present
    VQ-->>PP: state  {valid: true}
    PP->>FD: fetch_deal_data(state)
    note over FD: INTERNAL span — asyncio.gather (parallel)
    par parallel tool calls
        FD->>FD: rwa_engine_lookup(deal_id)   [CLIENT span + CircuitBreaker]
        FD->>FD: deal_db_lookup(deal_id)      [CLIENT span]
        FD->>FD: market_data_fetch(asset_class) [CLIENT span]
    end
    FD-->>PP: state enriched with rwa_usd, notional, rate
    PP->>CP: compute_pricing(state)
    note over CP: INTERNAL span — rwa_usd x rate / notional
    CP-->>PP: state  {indicative_price}
    PP->>CR: emit_compliance_record(state)
    note over CR: INTERNAL span
    CR->>CE: emit_compliance_event(event, config)
    CE->>CE: compute_chain_hash  [acquire _chain_lock]
    CE->>CE: sign_event  [HMAC-SHA256, under lock]
    CE->>FS: _write_to_store  →  append JSON line
    CE-->>CR: ComplianceEvent (signed + chained)
    CR-->>PP: state  {compliance_emitted: true}
    PP-->>EP: {deal_id, indicative_price, run_id, compliance_emitted}
    EP->>EP: detach baggage context token
    EP-->>MW: PricingResponse
    MW->>MW: response.headers["x-run-id"] = run_id
    MW-->>C: 200 OK  —  PricingResponse + x-run-id header

Compliance Chain Flow

How each ComplianceEvent is SHA-256 chain-hashed against the previous event and HMAC-SHA256 signed before being appended to the append-only JSONL audit log (thread-safe under _chain_lock). 

%%{init:{'theme':'dark'}}%%
sequenceDiagram
    participant ER as emit_compliance_record
    participant CE as emit_compliance_event
    participant LK as _chain_lock
    participant CH as compute_chain_hash
    participant SG as sign_event
    participant WS as _write_to_store
    participant FS as compliance_events.jsonl

    ER->>ER: hash_inputs({deal_id, price})  →  payload_hash
    ER->>ER: get_current_trace_id()  ·  get_current_span_id()
    ER->>ER: ComplianceEvent(type, run_id, actor, payload_hash, trace_id, span_id)
    ER->>CE: emit_compliance_event(event, config)
    CE->>LK: acquire _chain_lock
    CE->>CE: build signable dict  (exclude chain_hash + signature fields)
    CE->>CH: compute_chain_hash(signable, _previous_hash)
    note over CH: SHA-256(_previous_hash + json(signable))
    CH-->>CE: chain_hash  (64 hex chars)
    CE->>SG: sign_event(signable, hmac_key)
    note over SG: HMAC-SHA256(canonical JSON bytes)
    SG-->>CE: signature  (64 hex chars)
    CE->>CE: event.chain_hash = chain_hash
    CE->>CE: event.signature  = signature
    CE->>CE: _previous_hash   = chain_hash  [update module global]
    CE->>LK: release _chain_lock
    CE->>WS: _write_to_store(event_dict, store_path)
    WS->>FS: open(append)  ·  json.dumps line  ·  flush
    CE-->>ER: ComplianceEvent  (signed + chained)
